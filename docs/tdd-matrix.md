# Cognitive OS TDD Acceptance Matrix

This matrix converts every repository specification into an executable target. The legacy scaffold is treated as a starting point, not as evidence that a feature is complete. Each row follows AgenticLoop’s red → green → gate discipline: first express the required behavior as a failing test, then implement the smallest behavior that satisfies it, then run the full suite.

| Spec area | Acceptance behavior | Red test target | Green implementation target | Gate |
| --- | --- | --- | --- | --- |
| Provenance | Every stored node has a provenance level; invalid transitions and untraceable inferences are rejected. | `test_provenance.py` covers missing level, invalid upgrade, and missing `derived_from`. | Keep the enum and write/transition validators as the single enforcement point. | Full Python suite plus storage integration tests. |
| Deduplication | Exact normalized content matches are found; semantic matches above the threshold are surfaced; low-similarity records are not merged. | `test_dedup.py` covers exact and cosine cases. | Add persistent lookup integration and explicit conflict response. | Unit plus SQLite/store integration tests. |
| Graph/data layer | Writes require `schema_version` and provenance; agents cannot write committed graph data directly. | Existing graph-store tests assert early validation and explicit unimplemented behavior. | Replace the Kùzu placeholder with a local SQLite-backed graph-compatible store, with a migration boundary for future Kùzu. | Write, read, staging, commit, rollback, and migration tests. |
| RBAC | Owner can read/write/commit and manage roles; agents can read or stage only; no self-escalation. | Existing backend Jest RBAC tests plus route coverage for every permission. | Complete the permission matrix and use it at the route and service boundaries. | Full API authorization matrix and negative tests. |
| Audit logging | Every request is logged before/after execution; denied requests include reasons; history is append-only and queryable. | Existing Jest audit tests plus ordering and persistence tests. | Add timestamped persistent audit records and immutable read access. | API integration, restart/recovery, and append-only tests. |
| Request validation | Invalid bodies fail before handlers; every response includes a request ID. | Existing validation Jest tests plus route-specific schemas. | Complete route validators and response envelope. | Full route contract tests. |
| Guardrails | Quantified unsupported claims are flagged; provenance downgrades are rejected; duplicate origins are flagged; ineligible external output is rejected. | Existing guardrail tests. | Keep pure checks and invoke them in agent staging pipeline. | Agent staging integration and audit-event tests. |
| Agent layer | Registered agents pass through RBAC, guardrails, provenance, and telemetry hooks; rejected output never reaches staging. | Add orchestrator tests for pass, flag, reject, unregistered agent, and hook order. | Complete the registry runner and structured telemetry record. | Orchestrator integration tests with deterministic fake agents. |
| API | Health, journal staging, confirmation, agent invocation, audit, and role-management routes exist with correct status and authorization. | Add tests for every route and method from `api.spec.md`. | Implement route handlers against the local data/service layer. | Full backend Jest suite and HTTP smoke tests. |
| Runtime definition | Entries validate, preserve raw capture, write to SQLite and JSONL, generate weekly markdown, and detect backup corruption. | `tests/test_runtime_pipeline.py`. | Keep the existing reference scripts and expand shared integration coverage. | Clean-room Python suite plus JSON Schema validation. |
| Web UX | User can navigate dashboard, capture/review entries, inspect domains, and handle loading/empty/error states. | Add Playwright tests for navigation and core flows before styling. | Replace JSX placeholder with a buildable React app backed by the API. | Playwright Chromium at desktop and mobile viewport sizes. |
| Mobile UX | User can capture/review entries with safe-area handling, responsive layout, and working navigation. | Add an Expo-compatible component/e2e test plan; Maestro flows when a device/emulator is available. | Replace mobile placeholder with an Expo app using the shared API contract. | Type checks, component tests, and Maestro on Android/iOS device infrastructure. |
| Performance | Core API and review flows have explicit latency and error budgets. | Add repeatable load/performance checks before optimization. | Measure and optimize storage queries, payloads, and client rendering. | Local baseline plus representative load and browser performance runs. |

## Current known baseline

Before this implementation phase, the legacy scaffold had 25 passing Python tests and 12 passing backend Jest tests, but several tests intentionally asserted `NotImplementedError` and the client packages had no runnable build. The new implementation must preserve the passing contracts while replacing intentional stubs with working behavior where the specification demands it.

The test environment currently provides Chromium and a Playwright executable. Maestro, Expo CLI, and Android Debug Bridge are not available in the sandbox, so mobile-device tests require an external emulator/device runner. This is a test-environment limitation, not a reason to omit mobile acceptance criteria from the matrix.
